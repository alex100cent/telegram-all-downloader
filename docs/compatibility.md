# Совместимость и доказательства

Дата: 9 октября 2026. Версия расширения: 0.1.0.

Автоматическая проверка: TypeScript и ESLint без ошибок, **127 unit/integration-тестов и 8 E2E-сценариев пройдены**. Собранное MV3-расширение проверено в Chromium 156.0.8078.4: два адаптера, точный SHA-256, очередь, отмена, восстановление фонового процесса, поздний meta CSP без unsafe-eval и сохранение подключения после `history.pushState`/изменения `location.hash`. В двух последних сценариях после навигации внутри Web A успешно сохраняется синтетический файл. E2E использует собственные страницы Telegram и настоящий OPFS writer; нативный picker заменён тестовой функцией. Подробнее: [E2E](../tests/e2e/README.md).

Регрессии Web A покрывают восстановление кнопки после перерисовки, актуальную разметку вложений, потерю локальных метаданных, поздние RPC при замене/удалении сообщения и отмену повторной проверки источника. Эти проверки не заменяют сохранение реального файла через системный диалог.

Смена чата внутри SPA через hash/pushState сохраняет исходный документ и сессию расширения. Настоящая перезагрузка или замена документа, уход с поддерживаемого Telegram Web и закрытие вкладки прерывают зависимый от страницы путь. Одного события `chrome.tabs.onUpdated` со статусом `loading` недостаточно для признания сессии утраченной.

Проверка чистого исполнителя на синтетическом потоке 1 GiB подтверждает ограничение размера порций; она не является сетевой проверкой Telegram, измерением общего расхода памяти Telegram или проверкой записи 1 GiB на диск.

## Живая проверка Web A и Web K

9 октября 2026 в Chrome 155.0.8059.40 на macOS проверены реальные вложения шести типов из приватного канала с включённой защитой содержимого. Для выбора назначения использовался системный диалог. Интерфейс расширения показал `Saved` для **15 задач: восьми в A и семи в K**. Семь образцов сохранены обоими адаптерами, ещё одно фото — только через A. Файлы ненулевые и не изменялись во время проверки; размер и SHA-256 совпали во всех семи парах A/K. Команда `file` распознала форматы, `ffprobe` завершился с кодом 0 для каждого образца.

Все восемь уникальных образцов полностью декодированы FFmpeg 7.1.1 в `null` output: первые шесть — из K, дополнительный подкаст и фото — из A. Выбраны все видео- и аудиопотоки, включая встроенные обложки MP3; использованы `-xerror -err_detect explode`. Каждый запуск завершился с кодом 0 и пустым журналом ошибок; ошибок декодирования или усечённых кадров не сообщено. Повторное декодирование совпавших по размеру и SHA-256 копий другого адаптера не выполнялось. Изображения, аудио и видео при проверке не экспортировались и не воспроизводились.

Для первых семи строк размеры и SHA-256 одинаковы в A и K, включая фото с одинаковыми размерами изображения 554 × 554. Дополнительное фото через K не сохранялось.

При живой загрузке подкаста через A popup открыли на прогрессе 16% и закрыли клавишей Escape до завершения. Загрузка продолжилась, после чего интерфейс показал `Saved`. Сохранение дополнительного фото также подтверждено, но одновременное нахождение этих задач в очереди не зафиксировано: этот опыт подтверждает работу после закрытия popup, а не живую проверку очереди. Очередь покрыта отдельными автоматическими E2E-сценариями.

Отдельную загрузку аудио в Web K отменили кнопкой `Cancel` во время передачи. Интерфейс показал `Cancelled`; на диске остался созданный системным picker пустой файл размером 0 байт. Этот результат не учитывается как успешное сохранение. Живая отмена в Web A отдельно не проверялась.

Успешная серия Web A и седьмая загрузка Web K (подкаст) проведены после подтверждённой пользователем перезагрузки расширения из сборки ревизии **`3dcd7a9`** с исправлениями кэша A. Дистрибутив ZIP собран из той же ревизии; перед живой проверкой пройдены 127 unit/integration-тестов и 8 E2E-сценариев. SHA-256 ZIP: `e4342999429ca38dbead4c3f9124455aee88c2a1c174305c4ae3aa297e9a84a1`. Для предшествующих шести загрузок Web K точная загруженная ревизия не зафиксирована; сохранение подключения после смены чата с исправлением SPA подтверждено через интерфейс.

Сравнение подтверждает совпадение файлов, полученных двумя адаптерами. Ожидаемые серверные хеши исходных вложений неизвестны: совпадение A/K и полное декодирование не являются независимой проверкой побайтового равенства серверному оригиналу. Наибольший реально сохранённый образец — **29 109 155 байт (около 27,76 MiB)**; живое скачивание файла размером 1 GiB и расход памяти отдельно не проверялись.

Остальные форматы вложений, большие файлы и Яндекс.Браузер остаются непроверенными в живой среде. До заполнения живой матрицы нельзя считать обязательные критерии MVP из PLAN.md полностью пройденными. Для следующих результатов фиксировать браузер/build, A/K, тип файла, доступ публичный/приватный/protected, размер, ожидаемый и фактический хеш, поведение отмены и расход памяти. Идентификаторы частных чатов, исходные имена и содержимое файлов в этот документ не помещать.
