# Совместимость и доказательства

Дата: 9 октября 2026. Версия расширения: 0.1.0.

Автоматическая проверка: TypeScript и ESLint без ошибок, **126 unit/integration-тестов и 8 E2E-сценариев пройдены**. Собранное MV3-расширение проверено в Chromium 156.0.8078.4: два адаптера, точный SHA-256, очередь, отмена, восстановление фонового процесса, поздний meta CSP без unsafe-eval и сохранение подключения после `history.pushState`/изменения `location.hash`. В двух последних сценариях после навигации внутри Web A успешно сохраняется синтетический файл. E2E использует собственные страницы Telegram и настоящий OPFS writer; нативный picker заменён тестовой функцией. Подробнее: [E2E](../tests/e2e/README.md).

Регрессии Web A покрывают восстановление кнопки после перерисовки, актуальную разметку вложений, потерю локальных метаданных, поздние RPC при замене/удалении сообщения и отмену повторной проверки источника. Эти проверки не заменяют сохранение реального файла через системный диалог.

Смена чата внутри SPA через hash/pushState сохраняет исходный документ и сессию расширения. Настоящая перезагрузка или замена документа, уход с поддерживаемого Telegram Web и закрытие вкладки прерывают зависимый от страницы путь. Одного события `chrome.tabs.onUpdated` со статусом `loading` недостаточно для признания сессии утраченной.

Проверка чистого исполнителя на синтетическом потоке 1 GiB подтверждает ограничение размера порций; она не является сетевой проверкой Telegram, измерением общего расхода памяти Telegram или проверкой записи 1 GiB на диск.

## Живая проверка Web K

9 октября 2026 в Chrome 155.0.8059.40 на macOS сохранены шесть реальных вложений из приватного канала с включённой защитой содержимого. Для выбора назначения использовался системный диалог. Для всех шести задач интерфейс расширения показал `Saved`; сохранённые файлы ненулевые и не изменялись во время проверки размера и SHA-256. Команда `file` распознала форматы, `ffprobe` завершился с кодом 0 для каждого образца.

Все шесть сохранённых образцов также полностью декодированы FFmpeg 7.1.1 в `null` output: выбраны все видео- и аудиопотоки, включая встроенную обложку MP3, использованы `-xerror -err_detect explode`. Каждый запуск завершился с кодом 0 и пустым журналом ошибок; ошибок декодирования или усечённых кадров не сообщено. Изображения, аудио и видео при проверке не экспортировались и не воспроизводились.

Отдельную загрузку аудио отменили кнопкой `Cancel` во время передачи. Интерфейс показал `Cancelled`; на диске остался созданный системным picker пустой файл размером 0 байт. Этот результат не учитывается как успешное сохранение.

Точная ревизия расширения, загруженная в пользовательский Chrome для этой проверки, не зафиксирована. Сохранение подключения после смены чата с исправлением SPA подтверждено через интерфейс; перезагрузка расширения с последующими изменениями кэша Web A на момент записи результата ещё не подтверждена.

Локальные SHA-256 вычислены, но ожидаемые хеши исходных вложений не получены и сравнение с Web A ещё не выполнено. Распознавание формата и успешное полное декодирование сохранённых потоков не доказывают побайтовое равенство оригиналу. Наибольший реально сохранённый образец — **2 466 244 байта**; сетевое скачивание большого файла и расход памяти отдельно не измерялись.

Живые загрузки Web A, остальные форматы вложений и большие файлы остаются непроверенными. До заполнения живой матрицы нельзя считать обязательные критерии MVP из PLAN.md полностью пройденными. Для следующих результатов фиксировать браузер/build, A/K, тип файла, доступ публичный/приватный/protected, размер, ожидаемый и фактический хеш, поведение отмены и расход памяти. Идентификаторы частных чатов, исходные имена и содержимое файлов в этот документ не помещать.
